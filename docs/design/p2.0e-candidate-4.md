# ShareWise Phase B candidate 4: Common Ground

**Status:** Independent visual prototype for P2.0e Phase B review. This is a proposed direction, **not** an approved application design system or a statement that the illustrated finance features are implemented.

## Character and rationale

**Common Ground** combines an expressive editorial public website with the legibility of a small, well-organized financial ledger. Its visual language has four recognizable traits:

1. **Warm, human framing:** large, tightly spaced sans-serif headlines, selectively italicized Georgia phrases, friendly copy, and abstract circular motifs evoke shared occasions rather than banking dashboards.
2. **Financial precision:** tabular numerals, aligned amounts, clearly named payer/allocation/settlement concepts, revision markers, and generous row separation make the sample product screens plausible as day-to-day application UI.
3. **One restrained palette:** deep pine, paper-like neutrals, lively citron, and a small peach accent travel from the marketing hero to the product cards. Color is not the sole indication of credit/debit or historical state; amounts include signs and textual descriptions.
4. **Quiet interaction:** the prototype's actual interactions are anchor navigation and an appearance menu. The product views are static read-only illustrations, clearly labeled as such.

The design uses no remote imagery or fonts. The signature illustration is a composition of HTML, CSS, a small inline SVG brand mark, and locally defined fictional data.

## Shared theme and semantic tokens

[`src/frontend/lib/theme.ts`](../../src/frontend/lib/theme.ts) owns the proposed global Mantine theme and `cssVariablesResolver`. [`src/frontend/app/providers.tsx`](../../src/frontend/app/providers.tsx) applies both. The root `ColorSchemeScript` and provider use the same `auto` default; Mantine's color-scheme manager handles explicit light/dark selection and the persisted system choice.

The custom `clay` palette distinguishes Noah in avatar and participant illustrations, using darker foreground shades that remain legible on its light backgrounds. It is decorative participant identification, never the sole source of meaning. The custom ten-step `pine` palette spans `#edf6f0` to `#0d2b23`; its principal filled control uses `pine[8]` in light mode and `pine[7]` in dark mode. `citron` is a ten-step accent palette used for status labeling; its light steps start at `#f9fce9` and the highest shade ends at `#4e5d13`. Mantine retains ownership of default control states, hover/focus mechanics, and accessible behaviors.

Semantic properties distinguish the purpose of a color from a particular Mantine shade. Future product UI should use semantic properties rather than repeatedly hard-coding a new pair of light/dark colors. One-off decorative illustrations and **deliberately fixed-color preview canvases** may have local literal colors; these are not implicit global roles.

The base UI font is the locally available system stack, starting with Segoe UI, then system fonts. The editorial display accent is Georgia (`--sw-display-font`). No web font request is made. Mantine heading font-weight is `700`. Page headings use a denser scale with local negative tracking; application amounts use `font-variant-numeric: tabular-nums` to preserve column alignment.

Mantine's theme centralizes radii (`4 / 8 / 12 / 18 / 28px` from `xs` to `xl`) and spacing (`8 / 12 / 16 / 24 / 36px` from `xs` to `xl`). Standard `Button` uses rounded-pill (`xl`) radius, medium size and 700 weight; `Card` defaults to bordered, large-radius surfaces with standard padding; `Badge` defaults to light, pill-style labeling. The prototype does not implement alternate controls or a parallel component library. Layout spacing and illustration sizes live in the appropriate SCSS Module.

## Component ownership

- **Global:** `lib/theme.ts`, `app/providers.tsx`, and `app/globals.scss`. Global SCSS is intentionally limited to document background, selection, focus indication, and reduced-motion scroll behavior. Component themes use Mantine APIs rather than global selectors against internal markup.
- **Reusable application components:** `components/brand/Brand` owns the logo/wordmark, `components/navigation/AppearanceMenu` owns the color-scheme choice, and `components/finance/BalanceList` owns the list presentation for positive/negative participant balances. `BalanceList` accepts display data as props and does not import landing-page fixtures, back-end DTOs, or financial services.
- **Page-local illustrations:** `app/_components/{overview-preview,expense-preview,history-preview}` compose read-only examples with adjacent `*.module.scss` styles. They are not domain services, production dashboard screens, or prematurely reusable view frameworks. Their data comes from `app/_data/illustrative-ledger.ts`, independent of APIs or authentication.
- **Page composition:** `app/page.tsx` owns public copy, landmarks, navigation destinations, and the order of the sections; `app/page.module.scss` owns hero, ribbons, story layout, special dark feature section, and footer.

The illustrated “Sunday Table” group contains Maya, Noah, and Lina. Groceries cost €84 (paid by Maya), dinner cost €66 after a revision from €60 (paid by Noah), and transport costs €30 (paid by Lina). Equal allocations yield €60 per person. A €20 **external settlement recorded** from Lina to Maya changes the positions to Maya +€4, Noah +€6, Lina −€10. The historical snapshot at group revision 3, before the correction and settlement, is +€26 / +€2 / −€28. Both snapshots sum to zero. The timeline lists all five fictional group revisions in descending order. Revisions are ordered within the group, not across the application; the page does not imply that ShareWise transfers or verifies payments.

## Responsive, accessibility, and static behavior

The outer compositions use CSS Grid and Mantine's `Container` at wide widths. At `1120px` the hero stacks, at `860px` the major narrative/product columns stack, and at `560px` the illustrative overview becomes a one-column view with compact text and spacing. Site navigation collapses to still-working hero anchors and the always-visible appearance menu rather than adding a nonfunctional hamburger. Focus is explicit via `:focus-visible`; a skip link targets the `main` landmark. Decorative shapes are hidden from screen readers and static product previews contain no mock action buttons. Motion remains subtle; smooth scrolling is disabled under reduced-motion preference.

Mantine's appearance menu exposes **System preference, Light, Dark** and persists the chosen option via its color-scheme manager. The menu uses constant SSR labels rather than rendering an initially incorrect current-mode indicator from client-only storage. The document's root color-scheme script and provider default both use `auto` to avoid theme flashing. The test provider activates Mantine's `test` mode only during Vitest, disabling portal/transition timing artifacts in jsdom.

Static export requires no networking, backend, Next.js runtime, images, or font servers for this landing page. The unchanged legacy `/api/greetings` route and `/greetings` example are separate starter infrastructure and prevent a full-app export. A disposable export probe can omit those unrelated routes to test this prototype; no code in the candidate links to or uses them.

## Extending the candidate, if selected

Use Mantine for standard buttons, badges, cards, menus, and avatars. First identify a real cross-page responsibility before promoting a page illustration into a shared component. Consume the roles in `lib/theme.ts` and place composition-specific CSS beside its component. Keep domain balances and history as **display values** in presentational components, not arithmetic or HTTP operations. Future authenticated screens require their own approved application interfaces and validation; neither these mock layouts nor the visual prototype is a production contract.
